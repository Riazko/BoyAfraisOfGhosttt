## 1. Архитектура проекта

Проект сделан по логике MVC.

Главная идея архитектуры:

- `MainForm.cs` принимает ввод пользователя: клавиатуру и мышь.
- `GameController.cs` является главным контроллером и передаёт команды другим контроллерам.
- `GameModel.cs` хранит текущее состояние игры: игрока, призраков, карту, счёт, волну и окончание игры.
- `GameRenderer.cs` рисует игру, но не должен управлять игровой логикой.
- `Settings.cs` хранит общие настройки, чтобы не писать числа прямо в коде.

## 3. Что было сделано и где используются темы из задания

### 3.1. Стеки, дженерики, очереди

#### Стеки

Стек используется в `PathfindingController.cs` при восстановлении пути.

После того как алгоритм A* дошёл до цели, путь восстанавливается от конечной клетки к начальной через родителей узлов. Получается обратный порядок. Поэтому удобно складывать точки в `Stack<Vector2D>`, а потом извлечь их в правильном порядке.

Используется:

```csharp
Stack<Vector2D>
```

#### Дженерики

Дженерики используются во многих местах проекта.

Примеры:

```csharp
List<GhostModel>
List<Vector2D>
Dictionary<GhostType, Image>
Dictionary<(int, int, int, int), List<Vector2D>>
Optional<T>
Func<T, TResult>
Action<T>
```

Дженерики позволяют писать универсальный код, который работает с разными типами данных.

#### Очереди

Очередь используется в `HeatMap.cs`.

Там применяется BFS-обход карты, то есть обход в ширину. Для BFS нужна очередь:

```csharp
Queue<(int x, int y)>
```

Очередь работает по принципу: первый пришёл — первый вышел.

### 3.2. `yield return`

`yield return` используется в `PathfindingGraph.cs` в методе получения соседних клеток.

Смысл в том, что метод не создаёт отдельный список соседей заранее. Вместо этого он возвращает соседние клетки по одной.

Это делает код короче и показывает использование итераторов в C#.

Пример идеи:

```csharp
if (y > 0)
    yield return (x, y - 1);
```

В проекте это используется для получения соседей вершины графа.

### 3.3. Листы и словари

#### Листы

`List<T>` используется для хранения наборов объектов.

Примеры:

- `GameModel.cs` — список всех призраков:

```csharp
List<GhostModel>
```

- `GhostModel.cs` — текущий путь призрака:

```csharp
List<Vector2D>
```

- `PathfindingController.cs` — открытый список узлов для A*:

```csharp
List<PathfindingNode>
```

#### Словари

`Dictionary<TKey, TValue>` используется для быстрого поиска значения по ключу.

Примеры:

- `PathfindingController.cs` — кэш найденных путей:

```csharp
Dictionary<(int fromX, int fromY, int toX, int toY), List<Vector2D>>
```

- `GameRenderer.cs` — изображения для каждого типа призрака:

```csharp
Dictionary<GhostType, Image>
```

Словарь удобен, потому что можно быстро получить картинку нужного типа призрака или ранее найденный путь.

### 3.6. LINQ

LINQ используется для работы с коллекциями.

Основные места:

#### `GreedyFlashSelector.cs`

Используется для выбора призраков, попавших во вспышку:

- `Where` — фильтрация живых призраков;
- `Where` — фильтрация призраков внутри конуса света;
- `OrderBy` — сортировка по расстоянию до игрока;
- `Take` — ограничение количества целей;
- `ToList` — преобразование результата в список.

#### `GameRenderer.cs`

Используется `ToList`, чтобы сделать безопасную копию списка призраков перед отрисовкой.

Это важно, потому что призраки могут добавляться или удаляться во время работы игры.

#### `PathfindingController.cs`

Используется `Take` и `ToList` при очистке кэша путей.

### 3.7. Графы и обходы

Граф используется для поиска пути призраков.

Файл: `PathfindingGraph.cs`.

Карта игры представляется как граф:

- клетка карты — вершина графа;
- переход в соседнюю клетку — ребро графа.

Файл `PathfindingController.cs` использует этот граф для алгоритма A*.

A* ищет путь от призрака к цели. Для этого используются:

- начальная вершина;
- целевая вершина;
- список открытых вершин;
- множество закрытых вершин;
- стоимость пути `GCost`;
- эвристика `HCost`;
- итоговая стоимость `FCost`.

Также в `HeatMap.cs` используется BFS-обход.

BFS нужен для построения карты расстояний от игрока до остальных клеток.

---

### 3.8. Жадные алгоритмы

Жадный алгоритм используется в `GreedyFlashSelector.cs`.

Когда игрок делает вспышку, игра:

1. Берёт всех живых призраков.
2. Оставляет только тех, кто попал в конус света.
3. Сортирует их по расстоянию до игрока.
4. Берёт ближайших призраков в пределах лимита `MaxFlashKills`.

Такой подход является жадным, потому что алгоритм выбирает ближайшие цели прямо сейчас и не пытается строить сложную стратегию на будущее.

Также похожая жадная логика есть в `PathfindingController.cs` при выборе точки окружения игрока. Из доступных кандидатов выбирается клетка с минимальным значением `score`.

### 3.9. Динамическое программирование или похожая оптимизация

Классическое динамическое программирование в проекте почти не требуется, потому что игра работает в реальном времени.

Но есть похожие идеи: хранение уже посчитанных результатов, чтобы не пересчитывать их заново каждый кадр.

#### Кэш путей

Файл: `PathfindingController.cs`.

Для найденных путей используется словарь:

```csharp
Dictionary<(int fromX, int fromY, int toX, int toY), List<Vector2D>>
```

Если путь между теми же клетками уже был найден, его можно взять из кэша.

Это похоже на мемоизацию.

#### Таблицы HeatMap

Файл: `HeatMap.cs`.

Используются двумерные массивы:

```csharp
playerDistance[x, y]
ghostPressure[x, y]
```

Они хранят промежуточные значения для клеток карты.

Это похоже на табличный подход из динамического программирования: результат для каждой клетки сохраняется в таблице и потом используется в логике движения.

### 3.10. Многопоточность

Многопоточность в проекте используется для появления призраков во время игры. За это отвечает файл SpawnerThread.cs.

В обычной игре есть основной игровой цикл, который постоянно обновляет движение игрока, движение призраков, таймеры и перерисовку экрана. Если бы появление новых призраков выполнялось прямо в основном игровом цикле с задержкой, игра могла бы зависать. Поэтому спавн призраков вынесен в отдельный поток.
